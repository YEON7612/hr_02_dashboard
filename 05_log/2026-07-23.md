## Plotly 차트 2종 작성 + agents 데이터 갱신 이력 반영

[[agents]] 기반 eNPS 스코어카드(Plotly Indicator)와 번아웃↔CSAT 산점도(Plotly Express)를 작성하는 과정에서, BigQuery `agents` 테이블의 실제 위치와 값이 [[q-009-직원만족도-고객경험]]·[[i-004-직원만족도-고객경험]] 작성 시점(2026-07-22)과 달라진 것을 발견해 노트를 최신 값으로 갱신함.

### 진행 내용

- `charts/07_plotly_직원만족도eNPS스코어카드.py` — BigQuery agents 테이블을 직접 읽어 게이지(큰 게이지: 전체 eNPS) + 팀별 숫자 카드 3개로 구성한 스코어카드 작성
- `charts/08_plotly_번아웃CSAT산점도.py` — agents ⋈ consultations ⋈ satisfaction 조인으로 상담원별 CSAT 평균을 계산해 초과근무 시간과의 관계를 산점도 + OLS 추세선 + 상관계수 주석으로 시각화
- 두 스크립트를 실제로 실행하는 과정에서 `project1_day1.agents`(02_data/agents.md에 기록된 source)가 **빈 데이터셋**임을 발견 → `bq ls`로 확인해 실제 테이블이 `PROJECT1_DAY.agents01`(agents), `project1_day_03.consultations_table`/`satisfaction_table`로 옮겨져 있었음을 확인
- 같은 테이블을 재조회한 결과 `team`/`hire_date`/`employment_type`/`training_completed_yn`/`turnover_yn`/`qa_score`는 이전과 동일했으나, **`agent_satisfaction`·`overtime_hours_avg`의 상담원별 개별 값이 바뀌어 있었음**(값 범위는 동일: 2~9, 4~28)
- 이로 인해 전체 eNPS(-60.0 → -45.0), 직원만족도↔재문의율 상관(r=-0.233→-0.845, 유의하지 않음→유의함), 번아웃↔CSAT 상관(r=-0.086→-0.834, 유의하지 않음→유의함), tenure↔번아웃 상관(-0.813→-0.294, 유의함→유의하지 않음)이 모두 바뀜. 근속기간과의 얽힘은 `overtime_hours_avg` 쪽에서 약화됨

### 비고

- **주의**: [[05_log/2026-07-22]]의 "비고"에 따르면, 어제 세션에서 사용자가 상관계수를 "-0.86/-0.84(유의함)"로 언급했다가 당시 BigQuery 재계산값(-0.233/-0.086, 유의하지 않음)으로 정정받은 바 있음. 그런데 오늘 다시 계산한 값(-0.845/-0.834)이 어제 "잘못 언급됐다"고 기록된 수치와 거의 정확히 일치함 — 즉 데이터가 앞으로 계속 바뀐 것이 아니라, **원래 값으로 되돌아갔거나(revert) 어제 조회 시점의 테이블 상태가 일시적으로 달랐을 가능성**을 시사함. 어느 쪽이 "정본"인지는 이 세션만으로는 판단 불가 — 원본 데이터를 관리하는 쪽(강의/실습 환경 운영자 등)에 테이블이 두 번 바뀐 이유를 확인해볼 필요가 있음.
- 이 발견은 사용자에게 별도로 보고함.
